INCIDENT REPORT - Web Application Attack Activity, 15 March 2024

1. EXECUTIVE SUMMARY

On 15 March 2024, between 08:45 and 12:04 UTC, the web server came under several attacks from
external IP addresses, mixed in with normal user traffic. Analysis of the decrypted access log
identified three distinct attack types: brute-force password guessing against the login pages
(/login, /admin/login, /api/login, /wp-login.php), SQL injection against the search, product,
login and API endpoints (/search, /products, /login, /api/items), and directory traversal against
the file-serving endpoints (/download, /static, /files, /img, /view) aimed at sensitive system
files such as /etc/passwd and /etc/shadow. The main attackers used automated tools
(python-requests, Hydra, sqlmap, Nikto). One IP (141.98.10.33) used all three techniques. Some
payloads drew worrying responses: SQL injection requests returned HTTP 500 (the database query
broke) and HTTP 200 (the payload may have been accepted), and one traversal request for
/etc/hosts returned HTTP 200. Overall severity is HIGH. No successful login was confirmed, but
the 200/500 responses suggest the application may be vulnerable to SQL injection and file
disclosure, and these need urgent verification.

3. RECOMMENDED ACTIONS

Brute Force:
  Rate-limit and lock out login attempts (e.g. block an IP for 15 minutes after 5 failed logins,
  using fail2ban or the application/WAF), and enable multi-factor authentication on all accounts,
  especially /admin/login.

SQL Injection:
  Rewrite all database queries to use parameterised queries / prepared statements so user input
  is never concatenated into SQL. Run the database account with least privilege (no DROP
  permission), and verify the users and orders tables are intact.

Directory Traversal:
  Never build file paths from user input. Map requested files to an allow-list of IDs, or resolve
  the canonical path and reject anything outside the intended directory. Also reject encoded
  sequences such as %2e%2e%2f, which 77.88.55.60 attempted.

General: block the listed attacker IPs at the firewall/WAF, and use ./detect.sh in monitoring
(it exits 1 when an attack is found, so it can trigger alerts).
